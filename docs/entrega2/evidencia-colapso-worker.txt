Evidencia del colapso del Worker Server durante las pruebas del Escenario 2
Fecha: 2026-09-28, madrugada. Instancia: mooc-e2-worker (e2-small, 2 vCPU / 2 GiB).

Contexto: durante una corrida de carga con la API de pruebas y el worker
compartiendo la misma VM (worker+redis+clamav+API temporal), la instancia
dejó de responder por completo, incluyendo SSH.

Interpretación: la VM quedó tan saturada de CPU/memoria que ni siquiera
pudo completar una llamada local al servicio de metadatos de GCP (una
operación normalmente instantánea). Una petición de login tardó casi 10
minutos. Los health checks de Redis y ClamAV dejaron de responder. La
instancia se recuperó únicamente tras un reset forzado
(`gcloud compute instances reset`).

Causa más probable: concurrencia real de ffmpeg (transcodificación HLS) +
ClamAV + Redis, agravada por una API de pruebas corriendo en la misma VM
(desviación temporal de la arquitectura, ver sección de limitaciones).
